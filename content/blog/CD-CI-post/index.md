## CI/CD: страшные буквы или полезный инструмент?

Если ты хоть раз заглядывал в вакансии для разработчиков, наверняка видел требования типа «знание CI/CD», «опыт работы с Jenkins/GitLab CI/GitHub Actions». Звучит intimidating, но на самом деле всё не так сложно.

Давай разбираться.

### Что такое CI?

CI (Continuous Integration) — непрерывная интеграция.

Представь: над проектом работают несколько человек. Каждый пишет свой кусок кода. Если просто сидеть и ждать, пока все допишут, а потом пытаться это объединить — будет больно. Конфликты, ошибки, часы дебага.

CI решает эту проблему: код интегрируется в общую ветку постоянно, маленькими кусочками. И каждый раз, когда ты что-то добавляешь, автоматически:
- запускаются тесты
- проверяется, ничего ли не сломалось
- собирается проект

Если тесты упали — ты сразу узнаёшь и чинишь, пока не наплодил ошибок.

### А CD — это два в одном

Тут есть два варианта:

CD (Continuous Delivery) — непрерывная доставка. Код всегда в состоянии, готовом к выкатке на сервер. Хочешь — выкатывай хоть каждый час.

CD (Continuous Deployment) — непрерывное развёртывание. Код сам выкатывается на сервер после каждого успешного прохождения тестов. Вообще без участия человека.

Обычно под CD понимают и то, и другое, просто из контекста понятно.

### Как это выглядит на практике

Возьмём GitHub Actions — он встроен прямо в GitHub, и ты уже мог видеть его у себя в репозитории.

Ты создаёшь файлик .github/workflows/deploy.yml, и в нём описываешь:

```yaml
name: Deploy site

on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup Hugo
        uses: peaceiris/actions-hugo@v3
        with:
          extended: true
      - name: Build
        run: hugo --minify
      - name: Deploy
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./public
